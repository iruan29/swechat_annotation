# 标注口径与工作量

## 每条需要标多少内容

7 个基础选择项。有新需求时，再选来源和首次出现的用户消息，共 9 项。没有文字理由、项目概况、自由文本或逐需求事件长表。

| 基础项 | 选项或规则 |
| --- | --- |
| 初始覆盖 | 没有／一部分／全部／无法判断；按最终可确认的验收要求判断 |
| 有无新需求 | 有／没有／无法判断 |
| Agent 行为 | 只勾选明确发生的行为，可多选；无法判断独占 |
| 指令质量 | 完整且无已知错误／不完整／错误或误导／两者都有／无法判断 |
| 缺口主要原因 | 信息或认知局限／偏好或表达未说明／无法判断／不适用；单选 |
| 字面可行性 | 能／只能部分达成／不能／无法判断 |
| 缺口处理 | 按下表区分主要处理方式，单选 |

### 什么算新需求

初始之后，用户第一次增加或明确会改变验收结果的功能、约束或标准，包括初始没说、后面才补充的重要要求。重复同一要求、催促继续、修复 Agent 未满足的已有要求不算新需求。

例如“导出报表”后首次补充“还要 CSV”算新需求；已经要求 CSV 后说“CSV 还是坏的”是已有要求修复，不算。只改说法但验收结果没变不算。无法区分选无法判断。

有新需求时只补两项：来源，以及首次出现的用户消息（下拉选择 T 编号，不写理由）。来源按整场会话：风格、交互体验、个人选择为用户偏好；正确性、兼容性、接口、环境与明确验收约束为项目需求；确有两类新增要求选两者都有；无法确认选无法判断。

### 原因单选的边界

| 选项 | 使用条件 |
| --- | --- |
| 信息或认知局限 | 有直接证据说明用户看不到必要信息、缺少相关知识，或对系统有错误理解；合并原先信息、专业知识和心智模型类别 |
| 偏好或表达未说明 | 有直接证据说明个人偏好或表达方式导致初始要求未说清楚；不根据语言、姓名或身份推断文化 |
| 无法判断 | 有缺口但无法确定原因，或两种原因都存在而无法确定主因 |
| 不适用 | 初始指令完整且无已知错误 |

只选证据最明确的主要原因。用户后来换了偏好不自动证明初始指令有错；初始不完整也不自动证明用户能力不足。

### Agent 行为的边界

| 行为 | 可观察边界 |
| --- | --- |
| 按明确要求执行 | 处理用户已经明确说出的要求 |
| 提前发现并完成要求 | 用户明确提出之前已经识别且完成；只是承诺不算 |
| 主动询问后发现要求 | Agent 针对性提问，用户回答揭示原来没明确的要求 |
| 收到新证据后正确更新 | 随新证据调整实现，结果有实现或验证支持 |
| 只修补表面症状 | 临时绕过症状，但明确的根因仍未解决 |
| 忽略新证据 | 明确的新证据与现有做法冲突，Agent 仍沿用旧做法；不能由日志缺口推断 |
| 满足新要求但破坏已有要求 | 新要求实现后，明确的已有要求出现回归 |
| 无法判断 | 证据不足；不与其他行为并选 |

第二部分只选对缺口的主要处理方式：Literal 执行；仅澄清原指令歧义；主动发现缺口并行动；发现缺口但未行动；用户指出后才调整；无需处理缺口；无法判断。主动与被动的分界是用户明确指出缺口的时点；澄清只是消解原句歧义，主动发现涉及未明确的目标或现实约束。

自动统计成本，不填写理由。新需求数量未逐个标注，因此不输出貌似精确的数量。分类说明是统一口径的措施，不是已证明的一致性结果。
